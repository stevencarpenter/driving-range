# Standard runtime

`golf setup` builds the embedded Docker context. Setup needs network access. Practice uses only the locally cached image and never pulls automatically. The base image digest and jj 0.44.0 binary checksums are pinned for Linux arm64 and amd64. Debian package updates are resolved when building; `/usr/local/share/golf-packages.txt` records the installed versions. Every attempt records and reuses the resolved image ID, so rebuilding the tag cannot silently change an existing attempt's environment.

Exercises run as UID 1000 with a read-only base filesystem, no network, no Linux capabilities, and no privilege escalation. Each attempt owns one labeled Docker volume mounted at `/workspace`. No host directories, credentials, agents, or Docker sockets are mounted. The disposable home and temporary files live under a 64 MiB `/tmp` mount. CPU is capped at one core, memory and total memory plus swap at 512 MiB, processes at 128, open files at 256, and each file at 16 MiB. Interactive sessions stop after one hour; scripted submissions and individual validation commands stop after ten seconds. The Docker default seccomp policy remains enabled.

Returning from a shell or editor removes its entire container, including background processes, while preserving the attempt volume. Restart recovery removes containers only for the application's recorded attempts. Retry uses another volume. Deleting an attempt workspace requires an owner label matching the attempt ID.

Validation stops interactive containers first. File snapshots are decoded in memory, without extracting to host paths. Snapshots reject traversal, duplicate paths, links, devices, and FIFOs. They allow at most 4096 entries, 2 MiB per file, and 16 MiB total file data. Captured stdout and stderr each stop at 2 MiB. Stdout exercises replay the submitted file in a fresh workspace for every fixture. Repository queries run against independent copied snapshots inside new containers.

Docker volumes have no portable aggregate disk quota. A command can create many individually bounded files until its session deadline. Snapshot limits prevent loading those files into application memory but do not retroactively prevent disk consumption. Use curated exercises and a Docker VM with a configured disk limit. Direct interactive terminal handoff accepts normal terminal control sequences, including those printed by a user's command; captured output displayed by the outer TUI escapes control characters. Containers are an execution boundary, not a guarantee against kernel or runtime vulnerabilities, and local scores provide no adversarial integrity.

Run `GOLF_INTEGRATION=1 go test ./internal/runner -v` after setup to verify the execution boundary on the current Docker host. These checks create and remove only uniquely labeled test containers and volumes.
