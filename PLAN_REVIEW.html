EXPERIENCE

One useful daily

Three to seven minutes in the real editor or shell. A clear goal, a checkable result, and an explanation.

MVP CONTRACT

Every attempt survives

PRODUCT ETHOS

Correctness before compression

Teach useful operations and tradeoffs. Offer shortest-input optimization as an explicit replay mode.

Market fit is a hypothesis. SadServers already sells CLI/TUI access, and Exercism offers free CLI-first practice. The differentiation must be the daily habit, practical shell skills, editorial quality, and personal progress.

The shell is the product surface

Start one exercise. Work in the actual tool. Check the result. Save it. Leave after one useful repetition.

Thirty exercises means ten daily assignments per launch track. Start with a ten-day preview. Three fresh daily tracks would require an estimated 21 to 42 editorial hours per week, assuming one to two hours per exercise. Measure that cost before promising the cadence.

Design decisions that determine feasibility

Performance records are not proof of learning

Save all attempts and checks in SQLite. A retry creates a new attempt; resume adds a session. Compare results only across equivalent revisions, fixtures, assistance, profiles, and metric versions. Raw input bytes are not physical keystrokes. An unseen delayed task can investigate transfer; a faster replay can simply mean fixture memorization.

A workspace directory is not a sandbox

Standard exercises use a pinned Linux container with no host home, credentials, socket, or network, plus non-root execution and resource limits. Personal configuration practice is a separately labeled later profile. Never silently fall back to host execution. These controls require testing on both supported hosts. Docker runtime controls.

Use native terminal handoff before building terminal emulation

Propose Go and Bubble Tea with direct child processes, two initial validators, SQLite, and versioned filesystem packs. Prove child lifecycle and terminal restoration first. Bubble Tea supplies a child-process handoff API. No server, plugin ABI, ORM, or custom terminal emulator is needed for the local MVP.

Preserve vim-golf as an independent project

The inspected runner provides persistent Neovim workspaces, exact-output checks, and raw-byte scoring, but no general attempt ledger. Adapt the useful exercise format into the new project. Confirm licensing and remove undocumented personal-configuration assumptions before public reuse. No repository initialization, remote changes, or product implementation is part of this planning delivery.

RECOMMENDED LAUNCH

OSS + sponsorship

Free TUI, public dailies and archive, hints, full local history, and export. MIT application code and explicitly licensed public content.

Useful even if a subscription business never develops.

PRICE EXPERIMENT

Individual membership

Test $6/month or $60/year for managed sync/backup and dependable guided editorial delivery.

Demand is unverified. Sync alone may be insufficient.

LATER PILOT

Team programs

Test $150/month for up to ten participants: private exercises, onboarding sequences, and consent-based summaries.

Higher sales, privacy, and support obligations.

250 members at $6/month generate $1,500 gross monthly revenue, before all costs. At an assumed 5% conversion, 1,000 monthly active users generate $300. These are arithmetic scenarios, not forecasts.

Nearby evidence: SadServers lists $9/month Pro and $11/month Pro+; CodeCrafters offers individual and team memberships. Neither establishes willingness to pay for Driving Range.
